# 系统机制

> **适用阶段**：阶段二（在阶段一纯剧情之上接入）。阶段一不实现本文档中的 UI 与流程，但节点设计须 **预留接口**。

## 系统定位

系统是玩家扮演的伴生意识，具备更高维的信息视野（档案、轨迹、天机），与宿主通过 **心声** 交流。

## 心声规则（硬规则）

1. 宿主与系统的全部对话均为 **心声**，旁人 **看不见、听不见**。
2. 剧情中 NPC 不会回应「系统」；其他角色仅能对宿主的 **外在行为** 反应。
3. 心声在 UI 上与外在对话 **视觉区分**（见 [UI_LANDSCAPE.md](UI_LANDSCAPE.md)）。

## 联络规则（硬规则）

| 状态 | 是否联络 | 说明 |
|------|----------|------|
| 日常推进 | **否** | 宿主与系统不主动聊天；无系统对话面板内容 |
| 宿主请求帮助 | **是** | 宿主呼唤系统，触发 `host_call` |
| 宿主遭遇危机 | **是** | 标记 `crisis: true`，宿主紧急呼唤 |
| 系统初遇 | **是** | 宿主醒来，系统主动问候（唯一由系统发起的开场对白） |

**禁止**：无事时的闲聊、系统主动唠嗑（除初遇外）、宿主与系统商量日常琐事。

## 帮忙规则（硬规则）

当触发 **宿主请求** 或 **危机** 时：

- 系统 **必须帮忙**——玩家 **不能** 选择「拒绝」「不回应」「袖手旁观」。
- 玩家的决策空间是：**以何种方式帮、告知多少、指向哪条行动**。
- 每个 `host_call` 的 `responses` 中，所有选项都应构成「帮助」，语义可以是：
  - 直接告知真相或危险
  - 给出明确行动建议
  - 安抚并指向安全选项
  - 提供系统视角的情报（天机的一部分）

示例（合法选项）：

- 「别开门，门外的东西不是人。」
- 「躲到梁上，别出声。」
- 「现在去找燕赤霞，快！」

示例（非法选项，不得出现）：

- 「我不管。」
- 「你自己想办法。」
- 「（沉默）」

## 系统初遇

- **时机**：宿主某次 **醒来** 之后（可以是故事开场第一次醒来，或某次晕厥后醒来，由剧本定）。
- **内容**：系统问候 + 自我介绍 + 极简能力说明（如：「我在你心里说话，别人听不见」）。
- **宿主反应**：由剧情写定（惊恐 / 疑惑 / 强行镇定），可带一次简短心声回复，但不展开长聊。
- 初遇结束后回到 **日常静默**，直到下一次呼唤或危机。

## 系统可见信息（阶段二 UI）

附身期间，玩家可查看（不必然告诉宿主）：

| 信息 | 说明 |
|------|------|
| 宿主档案 | 姓名、身份、标签 |
| 人生轨迹 | 过去关键节点 |
| 天机预览 | 将发生的 1–3 件事（可模糊） |
| 终局目标 | 本宿主任务（若已设定） |

告知宿主与否，由玩家在 **系统回应** 的选项文案中体现。

## 撤离与串联（后续版本）

- **撤离条件**：终局目标完成，或宿主死亡。
- **初版 MVP**：可先只做宁采臣一条线结局，撤离与下一宿主作为阶段三。
- 撤离时播放结算，系统离开宿主。

## 阶段一预留（无系统时的数据结构）

阶段一事件节点建议预留字段（可为空）：

```json
{
  "hostCall": null,
  "systemAwakening": false,
  "crisis": false,
  "tianji": null
}
```

阶段二填入内容即可，无需重排主线。

## 当前不做的机制

- 抹杀宿主
- 系统能量 / 权限消耗
- 天道惩罚
- 拒绝帮忙
- 日常系统对话树

以上可在远期扩展文档中另行立项，默认 **不在当前版本实现**。
