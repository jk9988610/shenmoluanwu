# 开发阶段计划

## 总览

```
阶段一  纯剧情（无系统）     → 可玩通聊斋原著向互动故事
阶段二  接入系统             → 初遇、心声、求助/危机必帮
阶段三  串联与扩展（可选）   → 撤离、多宿主、存档 meta
```

每个阶段 **可独立交付、可部署 GitHub Pages**。

---

## 阶段一：纯剧情（初版目标）

### 目标

- 实现 **宁采臣 · 聂小倩** 完整互动线
- **不出现** 系统 UI、系统选项、系统文案
- 剧情 **尽量按原著** 推进（见 [WORLD_LIAOZHAI.md](WORLD_LIAOZHAI.md)）
- 手机横屏叙事 + 剧情选项
- 本地 / Pages 静态部署

### 交付物

| 交付物 | 说明 |
|--------|------|
| 事件引擎 v0 | 读取 JSON，推进节点与分支 |
| `ning_caichen` 剧情数据 | 全部节点文案与选项 |
| 横屏 UI（叙事区 + 选项区） | 无系统侧栏、无心声层 |
| 至少 2 个结局 | 与原著一致或合理分支（如宁死 / 双人脱身） |

### 技术栈

- Vite + Vue 3 + TypeScript
- 静态构建，`base` 配置适配 GitHub Pages
- 存档（可选）：仅记录当前节点，阶段一可简化

### 节点设计约束（为阶段二铺路）

编写阶段一剧情时 **必须**：

1. 在每个节点 JSON 中保留 `hostCall`、`systemAwakening`、`crisis`、`tianji` 字段（阶段一可为 `null` / `false`）。
2. 标记未来适合 **宿主呼唤** 的位置（在 `CONTENT_ROADMAP` 或节点 `notes` 中注明）。
3. 标记 **危机** 节点（夜叉、姥姥等），阶段二加 `crisis: true`。
4. 确定 **系统初遇** 插入点（建议：宁采臣兰若寺首日清晨醒来，或入寺前客栈醒来）。

### 阶段一完成定义

- [ ] 从开场到结局无死链
- [ ] 手机横屏 16:9 下无布局错位
- [ ] 主线与聊斋《聂小倩》核心情节一致
- [ ] `npm run build` 产物可部署

---

## 阶段二：接入系统

### 目标

- 在阶段一 **同一套节点 ID** 上增加系统层，不重写主线。
- 实现心声 UI、系统初遇、宿主呼唤、危机回应。
- 所有呼唤/危机回应选项 **必须帮忙**（见 [SYSTEM_MECHANICS.md](SYSTEM_MECHANICS.md)）。

### 增量功能

| 功能 | 说明 |
|------|------|
| 系统初遇 | 宿主醒来，系统问候与自我介绍 |
| 心声面板 | 与叙事区并存，仅在有 `hostCall` 或初遇时显示 |
| 天机/档案抽屉 | 系统视角信息，宿主默认不知 |
| 宿主呼唤 | `host_call.trigger` 为 `auto` 或条件触发 |
| 危机样式 | 紧迫 UI（配色、动效、文案缩短） |

### 阶段二完成定义

- [ ] 初遇可触发一次且仅一次（本线）
- [ ] 所有标记的呼唤点可对话，且无「拒绝帮忙」选项
- [ ] 危机点必触发呼唤，且选项均为帮助
- [ ] 日常节点无心声 UI
- [ ] 心声与外在对话视觉区分明确
